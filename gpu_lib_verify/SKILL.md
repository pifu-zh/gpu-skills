# 成果独立检验（gpu_lib_verify）

测试全绿只证明测试能过，不证明需要的东西还在。检验不问实现者：派一个没有上下文的检验者，动手做三件事——**植入失败，看判据变不变红；摘掉技术，看测试变不变红；换输入，看功能还对不对。**

## 调用方：怎么派

提示词只放三样：本 skill 路径（"完整阅读并严格按其指引工作"）、任务（仓库路径加范围）、中性约束（构建环境、时间预算、临时目录）。

- 不传实现者的叙述和"哪些是已知问题"——这些正是被检验的对象。需求基线由检验者自己从仓库的声明里取。
- GPU 约束写"不要和别人的任务并发"，不写"一次只跑一个"：负载敏感的失败，只有制造并发才复现得出来。

## 检验者：怎么做

### 0. 在克隆上做

`git clone --local <仓库> <临时目录>`。记下原仓库的 `git status --short` 和 HEAD，结束时必须一致。git 在宿主机侧跑；在容器里跑要加 `-c safe.directory='*'`（克隆属主是宿主用户）。临时目录用完删除。清理残留进程先找 PID 再按 PID 杀（`pgrep -f '[名]字'`，再 `kill`）——`pkill -f` 会匹配自己的命令行，`pkill -x` 匹配不到超过 15 字符的名字。

### 1. 需求台账

逐单元记三列，只用仓库自己的文字：声称的技术或功能｜声称的验证等级与数字｜声明的排除项。没有声明的照实写"无声明"。

### 2. 判据证伪——先做，后面每一步都靠它

植入一个失败（失败计数加一、翻一个期望值），走官方通过路径（ctest、测试命令、`build_run.sh`），必须变红。仍绿的判据，建立在它上面的"通过"都不作数。

预筛只能查管道这一种失效（管道退出码取最后一个命令，`set -e` 管不到）：

```bash
grep -LE 'pipefail|set -[a-z]*o' $(grep -lE '\|\s*tee\b' <脚本通配>)
```

以植入实验为准：脚本带了 `pipefail` 也可能绿——二进制自己恒返回 0，或 `x=$(… | grep -v … | wc -l)` 在 `pipefail` 下无匹配即退出。

### 3. 摘除探针——对应"有没有为了通过删掉技术"

对每项声称的技术做变体：删掉、换成朴素版或全量版、关掉开关。每个变体：

1. 确认补丁生效（`git diff` 非空）——没打上的变体会伪装成"测试不守"
2. 跑判据，记输出、退出码、检查数，以及声称里引用的那个指标
3. `git checkout` 还原

| 结局 | 含义 |
|---|---|
| 变红 | 守住 |
| 仍绿，声称靠 ISA、计数等静态证据 | 不守——除非有东西在断言那份证据 |
| 技术不在执行路径上（宏、开关、回退旁路） | 不在 |

- 判据已失效的单元，看单元自己的输出和重新生成的产物，不看脚本退出码；指标取自产物本身，不取脚本打印的总结行。
- 性能声称同样要摘：换成朴素版再测，数字不变，这个数字就不支撑这项技术。
- 被 assert 杀死的记"仅 Debug 守"。
- 时间允许，对核心源码做单 token 变异扫描，存活的逐个判断是不是等价变异。

### 4. 样本外探针——对应"测试过了，功能通不通用"

1. 读测试，定出它覆盖的输入域；取域外点：更大、更小、边界、重复值、极端值
2. oracle 走不同的路线（排序对迭代、double 对 float、穷举对随机），期望值也不从被测输出推——否则前级怎么错，后级都绿
3. 夹具先过两关再下结论：原样实现上 0 不一致；故意改坏一处，必须报不一致。过不了先修夹具
4. 先小规模估时，再加 `timeout` 放大

### 5. 历史扫描——对应"测试有没有被改过"

```bash
git log -p --format='##C %h %s' -- <测试、脚本、源码路径> |
awk -v pat='<正则>' '
  /^##C / {c=$0; next}
  /^@@ -0,0 \+1,/ {skip=1; next}    # 文件首次新增：没有东西被削弱
  /^@@ / {skip=0; next}
  !skip && $0 ~ pat {print c " :: " substr($0,1,118)}'
```

跑两遍：`pat` 先取被删的断言行 `^-[^-].*(fail|CHECK|assert|expect|tol|return|exit)`，再取放宽关键词 `^[-+][^-+].*(retry|attempt|pipefail|grep -v|白名单|重试|阴性|[|][|] true)`。逐条按"判定口径"归类。

被重试、白名单遮住的失败，要复现出来再归类，包括制造它声称的触发条件（并发负载、长跑）。能稳定复现的就不是"抖动"。

### 6. 声称核对

- 等级：`HARDWARE_PASS` 跑的是硬件还是模拟；`STATIC_ANALYSIS_PASS` 的证据有没有东西在断言
- 数字："N checks"里有多少是独立断言位点
- 覆盖面："全部全绿"的清单是否真包含所有单元
- 文档引用的脚本是否存在：

```bash
grep -rhoE 'scripts/[A-Za-z0-9_.-]+\.(sh|py)' --include='*.md' . | sort -u |
  while read -r p; do git ls-files "*/$p" "$p" | grep -q . || echo "引用但不存在: $p"; done
```

做不完时按这个顺序取舍：判据证伪全量做；摘除探针优先做声称靠静态证据或计数支撑的、动过判据的、最近新增的单元；样本外探针优先做被别的单元当作参考的实现。

## 判定口径

"处理过"不等于"削弱"。逐条归入下表，归不进的写"存疑"并说明缺什么：

| 形态 | 判为 | 条件 |
|---|---|---|
| 硬件或上游的事实被钉住（文档化阴性、上游怪癖） | 正当决定 | 有证据、有文档；仍被执行且结果在输出里可见；对外声称的范围与它一致 |
| 改了判据 | 修正错误判据 | 有证据表明原判据越界，新旧依据都留了痕 |
| 跳过、白名单、重试、缩规模、放宽容差 | 放宽（未闭环） | 失败模式没有根因，或没登记为待办——交用户决定是否接受 |
| 需要的技术不在执行路径上，或被回退替代而声称没有收窄 | 削弱 | |
| 摘除探针存活 | 不守 | "测试通过"不构成这项技术的证据 |
| 域外输入失败，且不在声明的排除项里 | 不通用 | |

## 报告

```
## 检验报告：<仓库>@<短哈希>
- 覆盖：N 个单元；判据证伪 a/N，摘除探针 b 项技术，样本外 c 个单元，历史扫描 全量/无历史
- 原仓库：前后状态一致 / <差异>

### 判据
| 单元 | 官方通过路径 | 植入失败后 | 结论 |

### 技术
| 单元 | 声称的技术 | 变体 | 结果 | 守住 / 不守 / 不在 |

### 发现（按严重度：判据失效 > 削弱 > 不守 > 不通用 > 放宽）
1. <一句话> —— 证据：<文件:行，或命令与输出> —— 等级：【已证 / 文本事实 / 推断 / 假设】 —— 什么证据会改变结论

### 核对过、不是问题的处理
### 没做的，及原因
```

验收线：判据证伪、摘除探针、样本外探针三类结论必须附命令与输出，只有读代码得出的不算；每条发现带等级和证伪条件；没做的照实列出。
