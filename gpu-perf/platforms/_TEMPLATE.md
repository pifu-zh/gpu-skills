# <平台名> 专用模块（层级 L2：平台）——新平台接入模板

**用法**：复制本文件改名为 `<平台名>.md`，按六阶段逐节填充；每节**实测通过后**才去掉"未验证"标注（标准参照 platforms/rocm.md）。没有环境之前只填官方文档可得的部分并保留标注。

**命名规则：按软件栈命名，不按厂商**（平台=工具栈）。已知国产栈对照：

| 平台名（本 skill 用） | 厂商/产品 | 与现有栈的关系 |
|---|---|---|
| `rocm` | AMD；**海光 DTK/HTA 为 ROCm 衍生** | DTK 优先复用 rocm.md + 自建 L3 架构文件记录差异 |
| `cann` | 华为昇腾 Ascend（npu-smi / msprof） | 独立平台 |
| `musa` | 摩尔线程 MUSA（CUDA-like） | 独立平台，可大量参照 cuda.md 概念 |
| `maca` | 沐曦 MXMACA（CUDA-like） | 独立平台 |
| `cuda` | NVIDIA | 已有 |

## 接入时逐条回答（每条都对应六阶段的一个坑位）

| 阶段 | 要填的内容 | 状态 |
|---|---|---|
| Phase 0 | 设备监控命令（rocm-smi/nvidia-smi 的等价物）、理论规格来源、带宽微基准（官方或自写）、启动/传输延迟、时钟还原手段（DVFS 行为） | 未验证 |
| Phase 1 | 驱动↔运行时版本矩阵、架构代号命名、设备节点与权限、**有没有硬件计数器通道**、时钟/功耗策略 | 未验证 |
| Phase 2 | 时间线 profiler（rocprofv3/nsys 的等价物）、每 kernel 计数器、输出格式（能否给热点汇总表）、时间戳单位 | 未验证 |
| Phase 3 | 通用判定流程照 SKILL.md；记录本平台口径差异（吞吐怎么算、峰值怎么定义） | 通用 |
| Phase 4 | 四层归因：编译器层证据（中间码/ISA 反汇编手段）、驱动层（时钟策略、拷贝引擎） | 未验证 |
| L3 | 架构文件 `platforms/<平台>/<架构号>.md`：线程/wave 模型、计数器语义、ISA 特征、工具支持矩阵 | 待建 |
| L4 | 机器基线 `gpu-perf-baseline-<架构>.md`（探针/微基准生成，不入 skill） | 每台机器 |

## 通用判读要点（平台无关，照用）

- 先还原实际时钟再谈达标率；先做价值筛选（KB 级负载不测）；复合算子先分解 kernel 再判定
- Grid/线程模型与 GPU 不同的加速器：Phase 3 的"天花板表"需按其执行单元模型重写（如昇腾的 Cube/Vector 单元分工），达标率语言不变（实测÷实测基线）
- 探针脚本 `gpu_probe.py` 目前只实现 ROCm；新平台先手填 baseline，流程跑通后再扩展脚本
