# 架构层：gfx1030（RDNA2 / Navi21）

层级：GPU（SKILL.md）→ 平台（platforms/rocm.md）→ **本文件：架构** → 型号/机器（项目本地 gpu-perf-baseline.md）。
本文件只写架构级事实（对同一架构的所有卡成立），不含具体型号规格与机器实测数字。架构号从 `rocminfo`（"Name: gfxXXXX"）确认。

## 架构属性（RDNA2）

- 计算单元 CU × 2 SIMD，wavefront 32/64 混用；无 MFMA（矩阵核）——GEMM 走 WMMA/VALU 路径，峰值算力远低于同代 MI 卡
- FP16 packed = 2 × FP32 吞吐；FP32 = 2 × 64 lane × clk / CU
- 消费级定位：L2 容量小、无 HBM、PCIe 主机接口——复合算子管线开销占比高
- DVFS 特征：短负载（单 kernel 数 ms）时钟爬升慢，实测可停在峰值的 15-20%——**判定前必须用 GRBM_GUI_ACTIVE÷时长 还原实际时钟**

## GCN/RDNA 系常用计数器（全集用 rocprofv3-avail 查，按架构略有差异）

- 指令混合（SQ）：`SQ_INSTS_VALU/SALU/LDS/FLAT/SMEM`、`SQ_WAVES`。SQ 类每 SE 各报一行（SE 数见 rocminfo "Shader Engines"），SUM=全卡值
- 访存：`FETCH_SIZE`（**单位 KB**，从显存取的字节数）、`GL2C_HIT/MISS`、`L2CacheHit`、`TA_FLAT_LOAD/STORE_WAVEFRONTS`
- 利用率：`GRBM_GUI_ACTIVE`（忙周期数，÷kernel 时长=实际平均时钟）、`GPUBusy`、`MemUnitBusy`、`VALUInsts`
- 占用/延迟：`OccupancyPercent`、`MeanOccupancyPerCU`、`LDSBankConflict`、`WAVE_DEP_WAIT`、`SQ_WAIT_ANY`
- 派生计数器（is_derived=1）带表达式，可查 `rocpd_info_pmc.expression` 看计算公式

**解读陷阱（实测教训）**：MemUnitBusy 高 ≠ 带宽饱和（访存指令频繁但每指令字节少时，busy 反映发射/等待频率而非字节吞吐）——判带宽瓶颈永远用 FETCH_SIZE÷时长 对比基线带宽。

## GCN/RDNA ISA 判读（`--save-temps` 产物 / llvm-objdump）

| 特征 | 含义 | 信号 |
|---|---|---|
| `global_load_dword` ×N | 标量 4B 访存 | 密集出现 = 未向量化；改 float4/向量化布局后应见 `dwordx4` |
| `v_fmac_f32_e32` | 融合乘加 | 正常（查有无多余指令序列） |
| `s_waitcnt` 密集 | 访存等待屏障 | 与长依赖链并存 = 延迟暴露 |
| `.reqd_work_group_size` / LDS 段 | 编译器强制的布局 | 与占用率联动分析 |
| scratch/spill 符号、`.scratch_` 段 | VGPR 溢出到内存 | 有 = 寄存器压力过大，降 VGPR 或限制每线程工作量 |

## 指令集支持实证（编译探针法，2026-09-09）

验证"某架构是否支持 X 指令"的最快方法：写最小 builtin 调用 + `hipcc --offload-arch=<目标>` 编译，**错误信息直接给出缺失的 target feature 名**（比查文档快且不会过时）。gfx1030 实测：

- `__builtin_amdgcn_mfma_f32_16x16x16f16` → **error: needs target feature `mai-insts`**（CDNA 矩阵核，gfx942 同 builtin 编译通过）→ MFMA ✗
- `__builtin_amdgcn_wmma_f32_16x16x16_f16_w32` → **error: needs target feature `wmma-256b-insts,wavefrontsize32`**（RDNA3+ WMMA）→ WMMA ✗
- fp8：ISA 无 fp8 类型/指令；aiter dtypes 回退 torch.uint8 是正确语义 → fp8 ✗
- bf16：无原生 bf16 FMA 指令（计算=bf16→f32 cvt→FMA），存储/转换可 → bf16 半支持（dtype→fp16 单变量 3.41× 的机制根源）

## 数据搬运能力（类 TMA 研究，2026-09-09 实证）

- **有**：MUBUF `buffer_load...lds` 直通 LDS（DRAM→LDS 不占 VGPR，目的=m0+lane*4 硬件扇出，m0 须 wave-uniform；`__builtin_amdgcn_raw_ptr_buffer_load_lds` 编译可用）——软件流水下可替代寄存器中转
- **有**：V# 描述符 OOB 硬件填零（经 builtin 不可关闭，恒有保护；num_records 4GiB 上限）——替代手写边界检查
- **有**：`s_clause N` 内存子句（MLP 硬件开关）+ `s_waitcnt vmcnt(N)` 部分排空（环形计数器，粒度=条数）
- **无**：`global_load...lds`（dlds 变体）、`ds_read swizzle`、任何硬件 swizzle（软件 padding 替代）、TMA/cp.async 类异步批量传输
- 软件流水三重代价：寄存器压力（VGPR 顶格→spill→串行化）、指令开销（每 dword 一对指令）、barrier 复杂度（全 wave s_barrier vs mbarrier）

## s_waitcnt 位域编码（GFX10.3 专属，llvm-mc 30+ 探针交叉验证）

- **gfx1030 与 gfx11 编码不同**：vmcnt=[3:0]+[15:14]（分裂）、lgkmcnt=[13:8]、expcnt=[6:4]；gfx11 是连续 vmcnt<<10|lgkm<<4|exp
- DSL/汇编生成器按 gfx11 连续编码会在 gfx1030 上静默错位（FlyDSL 适配实例）
- LLVM 对显式 s_waitcnt 有保守强化（无害时 vmcnt(1)→(0)）；s_waitcnt 只吃立即数，运行时值需退化 vmcnt(0)

- 主机内核驱动 amdgpu 6.19.14.31400100 对 code object v6 **部分支持**：可加载可执行但隐式参数（workitem/workgroup id 等）失效——"跑完但结果错"的隐性来源
