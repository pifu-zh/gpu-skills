# 反事实攻击调试法

## 目标

把“反事实攻击”用于编程调试：不凭直觉堆补丁，而是先提出当前领先的因果假设，再用受控反事实实验攻击它，定位真正的必要条件、充分条件和独立因果贡献。

核心问题：

> 当前假设是“X 导致 Y”。X 是 Y 的必要条件、充分条件，还是仅仅与 Y 同时出现？

- **X**：可疑输入、状态、配置、依赖、线程时序、缓存、环境差异或代码路径；
- **Y**：错误、错误输出、崩溃、性能退化、数据损坏或测试失败。

## 触发条件

当 bug 原因不明确、修补反复失败，或需要区分具体实现与结构/时序问题时使用。

## 核心流程

### 1. 固定现象与复现基线

先记录：

```text
现象 Y：
最小复现命令：
输入/环境：
预期结果：
实际结果：
复现率：
日志、堆栈、失败断言：
```

修改代码前先得到稳定基线。无法稳定复现时，缩小输入、固定随机种子、冻结依赖和环境，并记录复现概率。

### 2. 写出领先假设

使用明确因果句：

```text
H1：X 导致 Y，因为机制 M。
```

同时列出最多3个竞争假设，并记录支持证据、反证、未知项和预期观察。

### 3. 选择2—3种反事实攻击

优先选择信息增益最高、改动最小的攻击。**一次只改变一个变量，其余条件保持不变。**

#### ① 移除测试：But-for / 必要条件

问：如果移除 X，Y 还会发生吗？

- Y 仍发生：X 不是必要条件，降低 H；
- Y 消失：X 可能是必要条件，但不能据此证明 X 充分或直接致因。

#### ② 替换测试：变量特异性

把 X 替换为同类 X'，如依赖版本、实现、数据源、线程池、序列化器或配置值。

- 换成 X' 后 Y 不变：问题可能来自共同结构、接口或调用位置；
- 只有 X 触发 Y：X 本身更可疑。

#### ③ 剂量—反应测试

改变 X 的强度或规模：输入大小、并发数、序列长度、超时时间、batch size、缓存容量。

- Y 随 X 单调变化：支持因果贡献；
- Y 对剂量不敏感：X 可能只是相关因素，或存在阈值/离散触发器。

#### ④ 时序反推测试

改变 X 的发生时间、顺序或等待间隔。

- 只有特定顺序触发：优先怀疑竞态、生命周期或可见性；
- 时序变化不影响 Y：降低时序假设。

#### ⑤ 最小充分集测试：INUS 条件

把触发条件拆成集合，例如：

```text
Y = A（特定输入）+ B（缓存开启）+ C（并发写入）+ D（特定版本）
```

逐个移除或替换条件，寻找让 Y 消失的最小组合。不要把所有同时出现的因素都写成根因。

#### ⑥ 关键组件/执行者替换测试

替换函数、模块、驱动、数据库、模型、线程执行器或服务实现。

- 换组件后问题消失：组件或其契约更可疑；
- 换组件后问题仍在：可能是调用方式、共享状态或系统结构。

#### ⑦ 前提悬置测试

暂时否定假设依赖的前提：输入是否有效、返回值是否成功、锁是否生效、配置是否真的加载。

如果前提不成立，先验证前提，不要继续修补结论。

### 4. 设计最小实验矩阵

每个实验只改一个变量，并写出预期结果：

| 实验 | 唯一改变 | 若 H 正确，预期 | 实际 | 更新 |
|---|---|---|---|---|
| E0 | 原始基线 | Y 发生 |  |  |
| E1 | 移除 X | Y 消失 |  |  |
| E2 | X→X' | Y 消失/不变 |  |  |
| E3 | 降低 X 剂量 | Y 减弱/不变 |  |  |

优先执行成本低、可逆、区分度高的实验。

### 5. 用证据更新，而不是凭感觉裁决

实验结果只能改变置信度，不直接制造“证明”。使用以下状态：

- **保留**：反事实未击穿，但仍未证实；
- **降级**：部分预测失败，机制解释范围缩小；
- **淘汰**：出现可重复的关键反事实，因果链断裂；
- **重写**：X 不是根因，改为更小的条件组合或上游机制。

必须区分：

```text
观察到相关 ≠ 证明因果
反事实攻击失败 ≠ 假设成立
一次实验成功 ≠ 修复完成
```

### 6. 修复最小根因，并验证回归

修复应针对最小可解释因果集，而不是扩大容错、吞掉异常或添加未经验证的延迟。

完成：

1. 原始最小复现不再失败；
2. 回归测试固定触发条件和预期行为；
3. 相邻边界条件没有被破坏；
4. 在真实或等价环境中复测；
5. 删除临时日志、实验开关和无效补丁；
6. 记录未解决的不确定性。

## 常见陷阱

- 一次同时改动多个变量，导致实验无法归因；
- 把“移除后问题消失”误写成充分因果证明；
- 用反事实故事代替日志、测试和实际数据；
- 只攻击自己不喜欢的假设，不攻击领先假设；
- 把相关组件、共同上游和真正根因混为一谈；
- 用重试、sleep、吞异常掩盖竞态或生命周期错误；
- 看到一次成功就宣布修复，没有重复实验和回归测试；
- 反事实无限递归，超出当前可观测系统边界。

## 最小完成线

```text
稳定复现 → 写出领先假设 → 选择一种单变量攻击
→ 记录实际结果 → 更新假设 → 写一个回归测试
```

最终目标不是证明自己最初猜对，而是以最低成本找到能解释现象的最小因果机制。
