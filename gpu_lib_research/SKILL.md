# GPU 库研究（gpu_lib_research）

核心命题：研究不是读文档，是**带着 GPU 视角的定向盘查 + 实测互证 + 档案沉淀**。产出物是研究档案，不是聊天的回复。

## 铁律一：GPU 视角裁剪

只研究与 GPU 相关的部分。无关子系统（如通信库的网卡/IB 部分、构建系统的打包发布流程）**明确标记"不关心"**，不消耗研究精力。硬件缺失的部分用软件等价物替代并留位记录（例：无 InfiniBand 网卡时，RDMA 路径可用 soft-roce/RXE 内核模块模拟）。裁剪决策在立项时写进档案，研究过程中不摇摆。

## 研究五步

### 1. 立项
确定研究对象 + 研究目标（理解架构？恢复移植？评估接入？）+ GPU 相关性裁剪线。初始化档案：`~/workspace/docs/research/<库名>/README.md`，头部写清目标与裁剪线。

**长周期项目（"硬仗"级）立项模板**（cuda-oxide 实例）：盘查后产出分 Phase 路线图——每 Phase 有明确验收标准；"小步换件、每步可测"（每个 Phase 结束系统应处于可验证状态）；风险登记表（概率+缓解）；**每会话收尾落盘**（档案 phase 文件 + 记忆更新 + 阿里云同步）——会话可能随时中断，档案是唯一连续性保证。

### 2. 广度盘查（Explore 子代理）
派 Explore 子代理做结构化盘查，标准盘问清单（按对象裁剪增删）：

1. 它是什么（README 2-3 句概括）
2. 目录结构职责（一句话一个目录）
3. 构建系统与关键开关（**GPU 相关开关重点标出**）
4. 语言组成
5. 测试与基准入口（具体路径，能否在单卡/本环境快速跑）
6. 与 GPU 的关系（搜 gpu/cuda/rocm/hip 关键词，哪些模块涉及，几层）
7. 现状（已构建产物？移植/分支状态？本地修改与丢失的补丁？）
8. 快速上手路径（读什么、跑什么命令，原样引用）

编译器/DSL 类对象追加切入层问题：**产出的中间表示在哪一层是工具无关的？intrinsic/ABI/后端分发有没有现成挂点（枚举/trait/注册表）？**——挂点是移植的天然切口，设计者留的扩展门往往比想象多（cuda-oxide 实例：IntrinsicBackend 枚举 + .ll 文本出口）

要求：路径写全、命令原样、紧凑中文。**现状盘查必须含 git 状态与本地未跟踪文件**——移植补丁丢失/回退常发生（aiter 实例：gfx1030 补丁曾 10/10 UT 通过，同步上游后丢失）。

### 3. 深度研究
按立项目标定向深入：读核心源码（从盘查报告指出的入口文件开始）、跑最小路径验证理解。**实测先行**：写进档案的每条命令必须真机执行过；源码理解与运行行为互证，对不上时以实测为准并记录差异。

深度研究的派单要求（实战验证有效）：研究问题清单逐条编号，并要求**每条结论附源码文件:行号证据**；明确声明执行边界（"纯读码，不构建/不运行/不修改"或"可跑轻量实测"）；把已确认的盘查结论作为起点直接给子代理（不重做）；要求"实测与源码理解矛盾时以实测为准并标注"——矛盾处往往是文档/直觉错误，是最高价值的发现点。

### 4. 档案沉淀
- `README.md`：研究目标、裁剪线、进度、关键发现、后续行动（持续更新的主入口）
- 主题文档：一个深度主题一份（如 `<库名>-<主题>.md`，例：rocm-transport.md）
- 中文，命令原样引用，标注"实测/未验证"；发现的可复用坑写明适用条件

### 5. 回填
研究结论中可反哺其他 skill 的知识（新坑、新工具用法、基线数据）回写到对应 skill；跨库的共性发现（如两类构建系统的差异）沉淀为本 skill 的 L2 模板（库类型模板按需生长，不预建）。

## 研究纪律

- GPU 是共享资源：开工 `rocm-smi` 查占用，测量类操作避开他人负载
- 临时产物放 /tmp 专用目录，任务结束清理；档案目录是唯一持久产出
- 深度源码研究可派 general-purpose 子代理（给它盘查报告作起点 + 明确的研究问题清单），主代理负责落盘审核
- 多库并行研究时，涉及 GPU 运行实测的任务串行，纯读码任务可并行

## 层级

L1 本文件（方法论）。L2 库类型模板（C/autotools 库 vs Python/HIP 包的研究差异）待实战沉淀。研究档案（L4 实例数据）在 `~/workspace/docs/research/`，不入 skill。
